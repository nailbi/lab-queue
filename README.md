# Очередь на сдачу лабораторных работ (Laravel)

Курсовой проект: веб-сайт для электронной очереди на защиту лабораторных работ.
Студенты записываются в очередь без регистрации, староста управляет предметами,
очередью и расписанием семестра.

**Стек:** Laravel 12, PHP 8.2+, Blade, SQLite (по умолчанию), ванильный JS (AJAX),
тёмная/светлая тема. Авторизация — на базе Laravel Breeze, вход переделан на код.

## Что умеет

**Студент (без регистрации):**
- выбирает предмет на главной (видит счётчики очереди и число лабораторных);
- на странице предмета видит описание и **текущую очередь в реальном времени**
  (AJAX-автообновление каждые 5 секунд, без перезагрузки);
- вводит своё имя и отмечает нужные лабораторные **кнопками** (список лаб ведёт староста);
- встаёт в очередь — по одному предмету можно записаться только один раз
  (запись привязывается к браузеру анонимным токеном в сессии);
- видит свою позицию и может выйти из очереди (удалить можно только свою запись);
- смотрит **расписание семестра**.

**Староста (вход по 4-значному коду):**
- **Предметы:** создаёт / редактирует / удаляет, задаёт описание;
- **Лабораторные:** добавляет и удаляет кнопки лаб по каждому предмету
  («Лабораторная №1», «Лабораторная №2» …) — именно их выбирают студенты;
- **Заморозка записи:** открывает / закрывает запись в очередь по предмету.
  При закрытой записи новые студенты встать не могут, но уже записавшиеся остаются
  в очереди и могут из неё выйти;
- **Очередь:** двигает записи вверх/вниз, удаляет, отмечает явку —
  «Пришёл», «Сдал», «Не явился»;
- **Расписание семестра:** ведёт пары (день недели, время, аудитория, преподаватель,
  тип занятия, чётность недели — числитель/знаменатель).

## Нововведения последней версии

- **Заморозка записи в очередь** по предмету (поле `subjects.registration_open`).
- **Атомарная выдача позиций.** Постановка в очередь обёрнута в транзакцию с блокировкой
  строки предмета — при одновременной записи двух студентов они больше не могут получить
  одинаковую позицию (устранена гонка на `max(position) + 1`).
- **Вход старосты по 4-значному коду** вместо email/пароля (короткий код в `.env`,
  сравнение в постоянном времени, rate-limiter от перебора).
- **Покрытие тестами** ключевой логики очереди и заморозки (см. раздел «Тесты»).
- **Чистка кода:** удалён неиспользуемый скаффолдинг Breeze (страницы профиля,
  лишние Breeze-шаблоны), возвращена потерянная таблица `password_reset_tokens`.

## Как развернуть

Это содержимое приложения — его кладут поверх свежего Laravel-проекта,
потому что папки `vendor/`, `artisan`, `composer.json` и т.п. ставятся Composer'ом.

```bash
# 1. Создать чистый Laravel-проект и поставить Breeze (даёт страницы входа и routes/auth.php)
composer create-project laravel/laravel lab-queue-app
cd lab-queue-app
composer require laravel/breeze --dev
php artisan breeze:install blade

# 2. Скопировать файлы из этого архива поверх проекта:
#    app/                    -> app/
#    database/migrations/*   -> database/migrations/
#    database/seeders/*      -> database/seeders/
#    resources/views/*       -> resources/views/
#    routes/web.php          -> routes/web.php
#    config/auth.php         -> config/auth.php   (содержит ключ admin_code)

# 3. Настроить .env: БД (проще всего SQLite) и код входа старосты
#    DB_CONNECTION=sqlite
#    ADMIN_CODE=0000          # 4 цифры — обязательно смените!
touch database/database.sqlite

# 4. Применить миграции и создать старосту + демо-данные
php artisan migrate:fresh --seed

# 5. Запустить
php artisan serve
```

Открыть http://127.0.0.1:8000

### Вход старосты

- адрес: `/login`;
- вход по **4-значному коду** из переменной `ADMIN_CODE` в `.env` (по умолчанию `0000`);
- **обязательно смените код** перед развёртыванием;
- сидер создаёт саму учётную запись старосты — код лишь открывает к ней доступ.

|------|---------------|
| `tests/Feature/QueueFlowTest.php`         | запись в очередь, запрет повторной записи, выход только своей записи, управление кнопками лаб |
| `tests/Feature/RegistrationFreezeTest.php`| заморозка/открытие записи старостой, блок записи при заморозке, корректная выдача позиций |
| `tests/Feature/Auth/*`                    | вход старосты по коду и остальные сценарии авторизации |

## Сущности БД

- `subjects` — предметы (название, описание, кол-во лаб, **`registration_open`** — открыта ли запись);
- `labs` — кнопки лабораторных работ предмета (ведёт староста);
- `queue_entries` — записи в очереди (имя, названия лаб, кол-во, позиция, статус явки,
  `student_token` — анонимная привязка к браузеру студента);
- `schedule_entries` — пары расписания семестра;
- `users` — учётная запись старосты;
- `password_reset_tokens` — токены восстановления пароля.
